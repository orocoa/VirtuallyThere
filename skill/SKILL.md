# VirtuallyThere

中文名：不虚此行。Skill 的展示名称统一使用 VirtuallyThere。

用户提供文字或图片，Codex 负责理解、设计和执行，内部文件由工具管理。默认自动选方向，推进到模型交付与 Studio 导入；用户要求讨论或审图时停在该阶段。**不切片、不连接打印机、不上传或打印。**

## 设计与多角度参考

实际阅读文字、查看图片。提取“来源 → 关系／空间／感受／材料语言 → 完整物件”，不逐词拼零件，不编造日期和感情主题。新创作在 brief 的 `design_contract` 中分开记来源证据、设计解释与形体参数；顶层 `invariants` 是唯一的必保要求，写成能从模型视图判断的连接、开口、比例或识别线索。格式见[执行契约](references/execution.md)，用户无需填写。

默认克制、简洁、单色、有侧背深度的抽象造型，可刻少量文字。避免浮雕、微缩家具和无意义底座；展示桌面不入模，普通 PLA 不冒称玻璃或镀铬。以当前输入决定形体，上次作品不是通用模板。不主动引入装配、多色和精密工程。

生图时使用 imagegen skill 与内置 ChatGPT imagegen。每轮至少两张参考板：

1. 正面、右侧、背面。
2. 以第一组作身份参考，生成顶部、底部、前右斜视。

生图与建模使用同一 brief。主体固定、相机移动，Z 向上，正面 -Y、右侧 +X。看过全部输出后核对体量、连接、留白和刻字，区分遮挡与形体消失；细节不清时补对应局部角度。冲突须解决后再建模。生成图是形体参考，精确参数以 brief 为准；严格视图由实际模型渲染。

## 执行

先读取 [本地运行位置](references/runtime.json)，使用其 Python 与项目入口；首次或环境变化时运行 doctor。具体命令见 [执行契约](references/execution.md)。

流程：**定方向与多角度参考 → 建模／刻字 → 检查 → 导入 Studio**。新运行放独立 outputs 项目，保留来源与旧版本。

默认 Blender MCP，先体量，后细节和刻字；结构有歧义时才加体量预览。脚本读取注入的 `VT_BRIEF`／`VT_PARAMETERS`，复用造型操作而非固定作品模板，必要时自由建模。外部 Manifold 和字体操作使用 `VT_PYTHON`，不能假设 Blender 内置 Python 已安装它们。打印网格名 `VT_MODEL`，单位毫米、底部 Z=0；只关闭本任务的隔离实例。用户指定 Rhino 时走已有模型导入接口。

检查实际 STL 重导入的六视图与几何报告。逐项记录必保要求对应的视角和观察，不能仅填“通过”。失败定位到具体形体／参数再局部修改，不能加无意义底座或填掉关键留白。`MODEL_READY` 只表示几何与视觉检查通过、可进入切片器；壁厚、支撑、刀路和实物仍未认证。

`finish --review ... --open-studio` 交付 STL、编辑源、六视图和检查报告。观察 Studio 界面确认导入；`OPEN_REQUESTED` 仅代表请求已发出。到此停止。

## 省时与修订

已认可方向只重跑受修改影响的阶段。`revise-model` 保留概念、新开模型版本，可补丁更新参数；改变主体数量、连接方式、开口的存在或方向等概念要求时重新 brief 与生图。修订不能继承旧模型的通过状态。默认单代理、单个建模 GUI；无具体修复方案时报告阻碍，避免原样反复重试。

交付时说明保留的设计线索、检查范围与模型位置。分享图文是按需旁支，读 [分享规则](references/sharing.md)，不阻塞模型；区分概念、模型渲染与实拍，不编造打印进度。
